# Obsidian Knowledge

Base de conocimiento personal para construir competencias senior en:

- C y fundamentos de sistemas
- Java, Python y SQL
- Linux y administracion de sistemas
- LPIC, RHCSA y automatizacion
- Redes, Cisco y CCNA

El objetivo no es coleccionar apuntes. Cada tema debe convertirse en conocimiento que puedas explicar, ejecutar, verificar y aplicar en un proyecto.

## Empieza aqui

1. Abre [[Home]] para navegar por los dominios.
2. Consulta [[Roadmap]] para seguir el orden de estudio.
3. Lee [[Study System]] antes de crear notas nuevas.
4. Revisa [[Skills Matrix]] para medir avance con evidencia.

## Estructura


## Flujo de aprendizaje

```text
Pregunta o fuente
	↓
Concepto con dependencias y ejemplo minimo
	↓
Procedimiento o laboratorio reproducible
	↓
Fallo introducido y diagnostico
	↓
Proyecto integrador
	↓
Revision y explicacion sin consultar notas
```

Usa las plantillas correspondientes:

- [[Templates/Concept]] para explicar una idea.
- [[Templates/Procedure]] para una tarea repetible.
- [[Templates/Lab]] para experimentar y diagnosticar.
- [[Templates/Project]] para demostrar integracion.
- [[Templates/Source]] para procesar libros, cursos y documentacion.
- [[Templates/Study Session]] para estudiar y programar revisiones.

## Criterio de calidad

Una nota esta lista cuando responde:

- ¿Que es y que problema resuelve?
- ¿De que depende?
- ¿Cual es el ejemplo minimo?
- ¿Como se verifica?
- ¿Como falla y como se recupera?
- ¿Con que conceptos y proyectos se relaciona?

Leer una fuente no cambia el estado de una habilidad. El estado avanza cuando existe evidencia: un laboratorio, una prueba, un commit, un troubleshooting documentado o una explicacion propia.

## Convenciones

- Escribe definiciones con tus propias palabras.
- Enlaza prerrequisitos, conceptos relacionados y evidencia.
- Prefiere ejemplos pequeños que puedas ejecutar o verificar.
- Registra errores reales y su causa raíz.
- Mantén los proyectos reproducibles desde su README.
- No guardes secretos, credenciales ni datos privados en el vault.

## Estado del repositorio

La configuración personal de Obsidian puede cambiar entre dispositivos. Los cambios de `workspace.json` y `graph.json` no representan conocimiento y normalmente deben permanecer locales.
